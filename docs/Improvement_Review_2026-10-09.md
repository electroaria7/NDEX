# 전체 코드 감사 — 2026-10-09

## 검토 범위와 결론

0.9.3 이후 main 기준 전체 앱(NDEX One, Image Manager, Auto Selector, Frame, Launcher, ndex_common) 코드를 감사했다.
5개 영역을 병렬로 감사한 뒤 재현 또는 코드 추적으로 확인된 항목만 수정했다.
작업 브랜치는 `fix/audit-2026-10`이다.

## 재현하여 수정한 문제

### NDEX One

- **높음 — 한글 경로 촬영일 손실:** ExifTool 출력이 시스템 코드페이지로 해석되어 한글 폴더/파일의 RAW가 수정 시각 기준 날짜 폴더로 분류됐다. UTF-8 argfile과 `-charset filename=utf8`, UTF-8 디코딩, 경로 정규화 매칭으로 수정했다. 실제 ExifTool 13.55로 확인했으며, Image Manager의 메타데이터 읽기도 같은 방식으로 고쳤다.
- **중간 — 읽기 전용 원본의 임시 파일 잔존 및 덮어쓰기 실패:** 임시 파일에 고유 이름을 쓰고, 읽기 전용 속성을 해제한 뒤 삭제하거나 교체하도록 했다.
- **중간 — 취소한 백업 미기록:** 취소해도 백업 결과를 기록하며, 실행하지 못한 파일은 "not run: cancelled" 실패 항목으로 남겨 재실행할 수 있게 했다.
- **중간 — 대상 폴더가 원본 안에 있으면 매번 백업본을 다시 백업:** 대상 폴더를 원본 탐색에서 제외하고, 원본과 같은 폴더를 대상으로 지정하면 거부한다.
- **낮음 — 분석 중 취소 버튼이 동작하지 않음:** 분석 단계에는 취소 지점이 없으므로 분석 중에는 취소 버튼을 비활성화했다. 분석 중 사라진 파일은 경고를 남기고 건너뛴다.

### Image Manager

- **높음 — Send to Auto Selector가 Pick이 아닌 소스 폴더 전체를 넘김:** Auto Selector가 `.dsb_cache` 썸네일까지 선택 JPG로 읽어 Reject 포함 모든 RAW를 선택할 수 있었다. 이제 Pick한 JPG만 handoff 파일로 넘기고, Auto Selector에 `--handoff`를 추가했으며 `.dsb_cache`는 제외한다.
- **높음 — 다른 폴더의 같은 파일명끼리 RAW/JPG 짝:** RAW와 JPG의 짝을 폴더와 파일명을 함께 기준으로 맞춘다.
- **높음 — 파일 교체 후에도 이전 썸네일 표시:** 캐시 키에 수정 시각과 크기를 포함했다. 캐시 파일은 원자적으로 쓰고, 손상된 캐시 파일은 다시 생성한다.
- **중간 — 다시 스캔하면 백업 완료 상태 초기화:** 파일이 실제로 바뀐 경우에만 백업 완료 상태를 초기화한다.
- **중간 — XMP 내보내기 후 Pick 상태 변경이 반영되지 않음:** 내보낼 때 이전 NDEX 라벨/키워드를 제거한 뒤 현재 상태를 기록한다. Pick이 해제된 항목도 기존 사이드카에서 NDEX 상태를 제거한다.
- **중간 — 삭제된 파일의 카탈로그 행 잔존, 스캔 중복 실행 시 결과 섞임, 다중 선택 Pick이 한 장에만 적용:** 각각 수정했다.

### Auto Selector

- **높음 — 정확히 같은 파일명의 RAW가 있어도 "애매함"으로 건너뜀:** `IMG_1234-2.CR3`, `._IMG_1234.CR3` 같은 파일 때문에 후보가 여럿으로 집계됐다. 정확한 파일명을 우선하고 `._` 파일은 무시하도록 했다.
- **높음 — IMG_1234.jpg가 IMG_12345.CR3, Trip_IMG_1234.CR3에 조용히 매칭:** 카메라 ID 뒤에 경계 검사를 추가했고, RAW 쪽 ID는 파일명 시작에서만 인정한다.
- **높음 — rename 정책에서 같은 RAW가 `_001`, `_002`로 반복 복사:** 한 번의 실행에서 같은 RAW는 한 번만 복사한다. 동일 내용의 파일이 이미 있으면 건너뛰며, XMP는 사이드카가 없을 때만 작성한다.
- **중간 — 작업 폴더가 RAW 원본 안에 있으면 다음 분석이 모두 애매함:** 작업 폴더를 분석 대상에서 제외한다.
- **중간 — XMP 실패가 복사와 실패로 이중 집계되어 재실행 시 RAW 중복:** XMP 작성 실패는 한 건의 실패로만 기록한다.
- **낮음 — CLI가 recursive 설정을 기록하지 않음, 오류 시에도 종료 코드 0, 큐 처리 예외로 UI 정지:** 각각 수정했다.

### Frame

- **높음 — 내보내기 중 출력 폴더를 바꾸면 기록과 재실행 대상이 바뀜:** 작업을 시작한 시점의 출력 폴더와 프리셋으로 기록한다. 내보내기 중에는 관련 컨트롤을 잠근다.
- **높음 — ICC 프로필이 포함된 CMYK JPEG/TIFF 변환 실패:** 원래 색 공간에서 변환하고, 실패하면 기본 변환으로 대체하면서 경고를 남긴다.
- **높음 — 비 UTF-8 사용자 프리셋 하나로 시작 시 종료:** 프리셋 읽기 오류를 처리하고, 시작 시 상태 표시줄에 안내를 표시한다.
- **중간 — 16비트 그레이스케일이 흰색으로 잘림, 잘못된 배경색 프리셋이 모든 파일 실패, 가져오기 완료 시 내보내기 중 Export 버튼 재활성화:** 각각 수정했다.

### 공통 및 Launcher

- **높음 — BOM이 있는 settings.json을 빈 설정으로 읽음:** 다음 저장 때 다른 앱의 설정과 `.bak`까지 잃을 수 있었다. 이제 `utf-8-sig`로 읽고, 읽을 수 없는 파일은 `settings.json.corrupt-<시각>`으로 보존한 뒤 `.bak`에서 복구한다.
- **중간 — JPG 사이드카 작성 시 짝 RAW의 사이드카 내용이 섞임:** 보정값과 라벨을 자기 사이드카에서만 병합한다.
- **중간 — 기존 사이드카의 요소형 Rating/Label과 새 속성이 중복:** 요소형 값을 제거한 뒤 새 속성을 기록한다.
- **낮음 — 기타 Launcher 및 handoff 표시 문제:** 다른 폴더에서 작업한 뒤에도 Frame Continue가 이전 handoff를 여는 문제, Image Manager 카드에 잘못된 handoff가 표시되는 문제, Auto Selector로 보낸 기록이 Frame Continue와 "Send to Frame" 라벨로 표시되는 문제를 수정했다.

**동작 변화 (사용자에게 알려야 함):**

- RAW 파일명 앞에 다른 글자가 붙은 경우(예: `20240101_IMG_1234.CR3`)에는 카메라 ID로 매칭하지 않고, 정확한 파일명으로만 매칭한다.
- 취소한 백업도 Job Results에 남는다.
- Send to Auto Selector는 Pick한 JPG가 없으면 실행하지 않는다.

## 다음 개선 우선순위

1. **7B 범위를 그대로 우선한다.** Image Manager 백업, 내보내기, XMP 작업의 백그라운드 실행, Auto Selector와 Frame 취소 시 미처리 항목 기록, 종료 시 작업 정리가 여기에 속한다. 이번에는 NDEX One만 취소 기록을 넣었다.
2. **남은 확인 필요 항목:**
   - Frame 출력 프로필의 `embed_icc`, `chroma_subsampling` 필드가 인코더에 반영되지 않는다. UI는 고정값만 안내한다.
   - Frame 미리보기 캐시와 Image Manager 썸네일 캐시의 정리 정책이 없다.
   - 손상된 XMP 사이드카를 새 파일로 대체할 때 원본을 보존하는 처리(`.xmp.bad`)가 필요하다.
   - 설정 잠금 시간이 초과되면 기록 누락이 로그에 남지 않는다.
3. **7C/8B 후보:** 백업 전 여유 공간 확인, ExifTool 분석 진행률을 청크 단위로 표시, XMP/DOP 사이드카 백업(NDEX One은 현재 사이드카를 복사하지 않음), 동영상 CreateDate의 UTC 처리, Auto Selector의 애매한 후보 선택 UI, `.dng` 등 RAW 확장자 목록 통일.
4. **실기 검증:** 이번 수정 중 Tk/Qt UI 변경(취소 버튼, 스캔 세대, 컨트롤 잠금, Send to Auto Selector 흐름)은 단위 테스트와 코드 검토만 했다. 실행 파일로는 확인하지 않았다.
