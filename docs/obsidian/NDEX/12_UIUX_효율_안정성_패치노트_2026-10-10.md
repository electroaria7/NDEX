# 2026-10-10 — UI·UX·효율·안정성 개선

[[NDEX/10_패치노트|패치노트 목차]] · [[NDEX/Roadmap|로드맵]]

**현재 상태: 0.9.4 Beta에 포함, 재빌드·패키지 검증 완료.** 릴리스 대상은 GitHub `v0.9.4` prerelease이며, 배포 파일과 현재 검증 범위는 [[13_0.9.4_베타_배포_2026-10-10]]에 정리했다.

이 노트는 소스 개선 당시의 검토 기록이다. 당시 작업 브랜치는 `feat/uiux-review`, 버전은 `0.9.3 beta`였으며 소스 검증까지 수행했다. 이후 `0.9.4 beta`로 올려 5개 EXE와 설치본을 재빌드하고, 새 환경의 로컬·CI 검사 및 실제 EXE smoke를 완료했다. 아래 GUI 이벤트 루프 검증은 소스 실행 기준이며, 패키지 GUI 전체 상호작용 검증을 뜻하지 않는다.

## 검토 방법

서브 에이전트 3명이 Image Manager, Auto Selector, Frame/Launcher를 나누어 검토했다. 주 에이전트가 NDEX One/공통 모듈과 재현 근거를 재검토한 뒤 구현 범위를 확정했다. 구현 후에는 교차 코드 검토와 전체 회귀 테스트를 수행했다.

기존 2026-10-09 감사와 로드맵 7B를 바탕으로, 긴 작업의 화면 응답·취소·안전 종료·작업 결과 보존에 집중했다.

## 사용자에게 달라지는 점

### Image Manager

- 폴더 선택 버튼을 추가하고 작업 진행 표시와 Cancel을 제공한다.
- 백업·파일 내보내기·XMP 내보내기를 백그라운드에서 실행한다. 작업 중에도 화면 이벤트를 처리한다.
- 스캔/파일 작업은 한 창에서 한 번에 하나만 실행하며, 폴더 전환 중 이전 카탈로그를 사용하지 않는다.
- 스캔을 취소해도 기존 카탈로그/Pick/별점을 보존한다. 화면에서는 재스캔을 안내한다.
- 완료·취소·실패 내역을 Job Results에 저장한다. 결과 저장 실패는 경고로 알린다.
- 대량 Pick/별점/백업 상태를 한 DB 트랜잭션으로 갱신하며 선택을 유지한다.
- 최소 창 크기에서 진행·취소와 상태 문구가 겹치지 않도록 하단을 나눴다.

### Auto Selector

- 분석·복사·재시도 취소와 안전 종료를 추가했다.
- 작업 입력을 잠그고, 경로·하위 폴더 옵션이 바뀌면 이전 분석을 무효화한다. 복사 대상은 시작 시점에 고정한다.
- rename 재실행에서 기존 `_001` 등 번호가 붙은 RAW도 동일 파일이면 재사용한다. 같은 사진의 `_002`, `_003` 반복 생성을 막는다.
- 미처리 JPG를 취소 사유와 함께 기록하여 Job Results에서 재시도할 수 있다.
- 설정·작업 기록 저장도 worker에서 처리해 저장 잠금 대기 중 화면 응답을 유지한다.
- 종료 대기 중 작업/기록 오류가 나면 자동 종료를 취소하고 경고를 표시한다.
- 주요 화면의 CR3 표기를 RAW로 정리하고 분석 진행 표시를 보강했다.

### NDEX Frame

- 취소한 미처리 사진을 결과에 보존하여 Retry Failed 대상으로 복원한다.
- 사진 목록에서 취소 항목은 `Cancelled`, 완료 요약에서는 실제 오류와 취소 수를 구분한다.
- 창 닫기 시 GUI를 동기 대기로 멈추지 않고 작업 종료와 완료 기록 후 닫는다.
- 여러 가져오기가 겹쳐도 최신 요청만 화면에 적용한다.
- 동일 사진의 연속 프레이밍 조정은 decode 결과를 재사용한다. 원본 크기/수정 시각이 바뀌면 다시 읽는다.
- 예상치 못한 export worker 오류에도 스레드를 정리하고 실패를 알린다.

### NDEX One / 공통

- 원본·대상·파일 종류가 바뀌면 분석을 다시 요구한다. 작업 중 입력은 잠그며 백업 확인창은 실제 분석 목적지를 보여 준다.
- worker에서 결과 기록까지 처리하고, 닫기 요청 후 안전하게 종료한다.
- `rename`·`skip`·`smart` 백업 중 다른 작업이 같은 이름을 생성해도 해당 파일을 덮어쓰지 않는다. 충돌을 실패로 기록해 기존 파일을 보존한다.
- 제외할 백업·작업·캐시 폴더를 탐색 전에 제거한다.
- Launcher에서 Manager의 백업·내보내기 최신 결과와 XMP 작성 수를 표시한다.

## 효율 검증

| 항목 | 이전 | 개선 후 |
| --- | ---: | ---: |
| Frame 같은 사진 프레이밍 20회 변경 시 decode 요청 | 20개 | 1개 |
| 원본 25개 + 제외 백업 하위 폴더 200개 합성 트리 탐색의 디렉터리 읽기 | 404회 | 1회 |
| 위 탐색의 반환 파일 수 | 25개 | 25개 |

합성 트리 단회 시간은 20.18ms → 0.72ms였다. 실제 SD카드·RAW 전체 작업의 성능 보장값은 아니다.

**전체 472개 통과, 기준선 433개에서 회귀 테스트 39개 추가.**

| 영역 | 테스트 수 |
| --- | ---: |
| 공통 / NDEX One / 통합 | 204 |
| Image Manager | 29 |
| Auto Selector | 54 |
| Launcher | 14 |
| Frame | 171 |

- Windows / Python 3.12.10. 설정·기록은 임시 폴더로 격리했다.
- 실제 Tk 이벤트 루프의 응답·취소·종료·오류 복원과 Manager 최소 1040×680 배치를 확인했다.
- 실제 Qt 이벤트 루프의 종료 대기·완료 기록 및 취소 사진의 재시도 복원을 확인하고 offscreen 화면을 점검했다.
- `compileall`, `git diff --check` 통과.

## 동작 한계와 남은 검증

- 취소는 현재 파일의 복사·검증·XMP/인코딩을 마친 후 적용한다. Manager 스캔은 현재 메타데이터 배치(최대 100개) 완료를 기다릴 수 있다. One 분석 중 닫기는 분석 완료를 기다린다.
- 이미 완료한 파일은 보존한다. 미처리 파일은 기존 재실행과 호환되는 `failed / not run: cancelled` 상태로 기록한다.
- Manager 전용 Retry Failed는 아직 없으며 Job Results에서 미처리 경로를 확인한다.
- Manager의 전체 메타데이터 재읽기와 Treeview 재작성, 캐시 용량 제한, 여유 공간 사전 점검은 후속 작업이다.
- 실제 대량 카메라 RAW·SD카드 성능, Lightroom/Evoto XMP 호환성, 0.9.4 신규 설치·업그레이드는 미검증이다. 새 EXE·설치본 빌드와 패키지 기본 검증은 후속 [[13_0.9.4_베타_배포_2026-10-10]]에서 완료 범위를 구분했다.
- Frame 종료가 항상 기록을 잃는다는 초기 가설은 재현되지 않아 기각했다. 확인된 문제인 UI 동기 대기와 timeout 이후 종료 확인 부족을 수정했다.
