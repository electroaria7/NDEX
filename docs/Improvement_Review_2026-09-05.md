# 개선 및 브랜치 검토 — 2026-09-05

## 검토 범위와 결론

원격 브랜치를 갱신하고 main과 각 브랜치의 커밋 포함 관계를 확인했다.
미병합 변경은 `feat/phase-6-handoff-and-retention`의 PR #13 하나다.
앱 간 handoff 계약 테스트, 작업 기록 보관 정책, export 집계 명칭 수정은
유지할 가치가 있어 아래 결함을 보완한 뒤 merge commit으로 반영한다.
나머지 로컬/원격 작업 브랜치는 main에 포함된 것을 확인한 후 삭제한다.

## 재현하여 수정한 문제

- **높음 — 일반 JSON 삭제 가능:** retention이 `backup-` 같은 접두어만
  검사해서 `backup-notes.json`까지 삭제했다. 생성되는 timestamp 파일명
  전체와 일치하는 파일만 대상으로 제한했다.
- **높음 — 보호할 기록의 읽기 오류:** 세션 폴더 접근 오류가 정리 밖으로
  전파될 수 있었고, 설정 읽기 실패가 빈 보호 목록으로 취급될 수 있었다.
  정리 경로에서 I/O 오류를 엄격히 전달하고 보호 목록 수집 실패 시 삭제를
  건너뛴다. 실제 Path.open 권한 오류를 주입하는 테스트도 추가했다.
- **중간 — 세션 JSON 형식 오류:** 배열/null/문자열/숫자를 세션으로 읽으면
  AttributeError가 발생했다. 객체가 아닌 JSON은 무효 세션으로 처리한다.

## 다음 개선 우선순위

후속 진행: 1번의 동시 실행 보호를 구현했다. 새 프로세스 테스트 4개는 기존
main 코드에서 모두 실패했으며, 특히 같은 초에 생성한 12개 기록 중 3개만
남는 덮어쓰기를 재현했다. 공통 프로세스 잠금으로 기록 생성·세션 갱신·보관
정리를 직렬화하고 Windows 설정 잠금의 경합 오류도 수정했다. 아래 1번은
최초 검토 당시의 발견 내용이다. 후속 전체 테스트는 364개가 통과했다.

1. **다중 프로세스 기록 일관성:** `ndex_common/manifest.py::_unused_path`는
   존재 검사 후 파일을 쓰므로 같은 앱의 동시 실행에서 같은 이름을 선택할
   여지가 있다. `session.remember`의 읽기-병합-쓰기와 retention의 보호 목록
   읽기-삭제도 하나의 트랜잭션이 아니다. 프로세스 공통 잠금 또는 배타적
   파일명 예약을 검토하고 동시 실행 재현 테스트를 추가할 것. 코드에서
   확인한 경쟁 가능성이며 이번 검토에서 실제 충돌을 재현하지는 않았다.
2. **실제 UI와 배포본 흐름 검증:** 새 통합 테스트의 Frame export는 대역이다.
   별도의 Qt 테스트는 있지만 설치된 실행 파일 간 인자 전달, 실제 이미지
   export, 설치 업그레이드는 별도 검증이 필요하다.
3. **기록 용량과 내보내기:** type별 100개는 파일 수 기준이며 보호된 파일은
   추가로 남는다. `workflow.trim_items`는 실패 내역을 모두 보존하므로 대량
   실패 시 파일 크기는 제한되지 않는다. 실제 대량 작업 측정 후 용량 정책과
   사용자용 CSV/JSON 리포트 내보내기를 검토할 것.
4. **사용성 및 릴리스 정리:** Auto Selector의 한국어 UI와 다른 앱의 영어
   용어를 통일하고, 로드맵에 남은 기존 1.0.1 설치본의 업그레이드 경로와
   배포본 서명 계획을 정리할 것.
